## 1. GDR（General Decision Record）

**GDR-META-016: `notes/_archive/` 領域を導入し、AI のデフォルト読み込みから除外する**

- **status:** Proposed
- **scope:** meta, pol
- **決定:** `notes/_archive/` を top-level に新設し、`notes/_archive/{元のディレクトリ}/{元のファイル名}` の形で**元のパス構造を保持して**退避する。AI（Claude Code / Cursor / Copilot）は本領域を**デフォルトで読み込まない**。ユーザーが明示パス（例: `notes/_archive/20_kaizen/2026-05-01_old.md` を読んで）を指定した場合のみ AI が参照する。物理削除は AI が触らずユーザー手動 (`rm`) で行う
- **理由:** ビルドアップ記録・改善提案・Superseded GDR が蓄積するにつれ、AI セッションのトークン消費が線形に増える（既知のデメリットとして [02 §3.3](/01_GDR/02_AI_DRIVEN_GDR_BUILDUP.md#33-デメリット留意点) に列挙済み）。「捨てる」と「残す」の二択しかない現状では、過去判断の参照可能性とトークン節約の両立が困難。`_archive/` を AI 文脈から除外しつつパス構造を保持することで、復元時の `mv` 1 コマンドで元の位置に戻せる。`_` プレフィックスは標準ディレクトリの番号体系（01〜99）の外側にあることを命名で明示する役割を持つ
  - **代替案 A:** `notes/99_archive/` で番号体系に乗せる → 90 番台の他のメタ系（`91_gdr/`）と区別しにくく、AI への除外指示が曖昧になる。却下
  - **代替案 B:** 各バケット内に `_archive/` を分散配置（`notes/20_kaizen/_archive/`） → 除外ルールの説明が複雑化し、AI が一括除外する設定が書きにくい。却下
  - **代替案 C:** archive せず削除 → 判断履歴が消える。GDR の「再検討条件」運用と矛盾するため却下
- **影響:**
  - [03_FIRST_PROMPT_GUIDE §2.2](/01_GDR/guide/03_FIRST_PROMPT_GUIDE.md) の標準ディレクトリ構成テーブルに `notes/_archive/` 行を追加し、AI 除外の注記を入れる
  - 推奨 CLAUDE.md テンプレ（プロジェクト直下）に「`notes/_archive/` は AI セッション開始時の読み込み対象外」を明記する
  - Claude Code 利用者向けに `.claude/settings.json` の `permissions.deny` / `hooks.PreToolUse` での技術的強制例（任意）を [05_CLAUDE_CODE_SETUP](/01_GDR/guide/05_CLAUDE_CODE_SETUP.md) に追加する
  - 復元は `git mv notes/_archive/20_kaizen/xxx.md notes/20_kaizen/` の 1 コマンドで成立する（パス構造保持のため）
- **再検討条件:**
  - `_archive/` 配下のファイル数が数百を超える → 物理ストレージや diff 表示の負担が顕在化、自動削除ポリシーの検討
  - 「完全除外」が運用上不便と判明（例: 横断レビュー時に過去判断を参照したい頻度が高い） → `_archive/INDEX.md` のみ読み込む方針（軽量参照）への変更
  - 主要 AI ツールがディレクトリ除外を技術的にサポートしなくなる場合


**GDR-META-017: アーカイブ用短縮キーワード「アーカイブ：」と `/gdr-archive` を追加する**

- **status:** Proposed
- **scope:** meta, pol
- **決定:** 既定短縮キーワードに `アーカイブ：[ファイル or ディレクトリ]` を 6 種目として追加し、対応するスラッシュコマンド `/gdr-archive <パス>` を `~/.claude/commands/gdr-archive.md` で提供する。動作は「対象ファイルを `notes/_archive/{元のディレクトリ}/{元のファイル名}` に移動し、コミット」までを 1 アクションで実行
- **理由:** アーカイブは恒常的に発生する運用アクションであり、毎回「これを `notes/_archive/{...}` に `mv` して」と書くと冗長。GDR ビルドアップが既に `改善提案：` / `レビュー：` / `バグレポート：` / `一気通貫：` の 5 種でキーワード化していて、`アーカイブ：` も同じレベルの頻度になる見込み。`アーカイブ` の語は IT 用語として日本語環境で定着しており、スラッシュコマンド `/gdr-archive` とも語感が一致するため採用（`退避：` も自然な候補だが、コマンド名英語と日本語キーワードを分けるより統一の方が学習コストが低い）。スラッシュコマンドを並設するのは [04 §6](/01_GDR/guide/04_PROMPT_GUIDE.md) 同様のハイブリッド方針（自然文中はキーワード、補完で発見性が必要な場面ではスラッシュ）
- **影響:**
  - [04_PROMPT_GUIDE §6](/01_GDR/guide/04_PROMPT_GUIDE.md) の定義済みキーワード表が 5 種 → 6 種に拡張される
  - [05_CLAUDE_CODE_SETUP](/01_GDR/guide/05_CLAUDE_CODE_SETUP.md) の配置ファイル一覧が 6 → 7 ファイルになる（`gdr-archive.md` 追加）
  - user-level `~/.claude/CLAUDE.md` の既定キーワード対応表に 1 行追加
  - 配置プロンプト（[00 §Step 2.0](/01_GDR/guide/00_GETTING_STARTED.md#step-20-claude-code-利用者のみ-global-config-を配置する)）の要件部分も同期更新が必要
- **再検討条件:**
  - キーワード総数が 8 種を超えて運用上煩雑になる → 統廃合の検討
  - スラッシュコマンドの引数仕様（複数ファイル / ディレクトリ）が破綻


**GDR-META-018: Superseded GDR は `GDR_INDEX` に 1 行サマリを残して本文を archive へ退避する**

- **status:** Proposed
- **scope:** meta
- **決定:** GDR が Superseded になった場合、`GDR_INDEX` には「`GDR-OLD-NNN`（決定の要約） — **Superseded by `GDR-NEW-MMM`** → archived」の 1 行サマリを残し、GDR レコード本文ファイルは `notes/_archive/91_gdr/gdr/` 配下へ退避する。AI は INDEX の 1 行で「過去にこの判断があり、新しい GDR に置き換わった」を把握できるため、議論詳細を読まずに**再検討条件と置換関係の追跡**が可能
- **理由:** [01 §3](/01_GDR/01_GENERAL_DECISION_RECORD.md#3-書式) の Superseded 運用は「相互リンクで判断履歴を追跡可能にする」が目的。だが現状は旧 GDR 本文を残し続けるため、Superseded が積み上がると AI トークン消費に効いてくる。本決定により「**Superseded 状態の宣言は INDEX、議論詳細は archive**」の二段構成にする。GDR-META-016 の完全除外ポリシーと組み合わせることで、INDEX だけ AI が読み、詳細議論は読まずに済む
- **影響:**
  - [01 §3](/01_GDR/01_GENERAL_DECISION_RECORD.md) の Superseded 説明に「本文 archive ＋ INDEX 1 行サマリの二段保管が推奨」を追記
  - [02 §5.2](/01_GDR/02_AI_DRIVEN_GDR_BUILDUP.md#52-判断は積み上がるincremental-crystallization) の判断更新時運用ルールに二段保管を追記
  - `GDR_INDEX` の書式に Superseded 行の例示を追加
  - 既存プロジェクトへの遡及適用は強制せず、運用者の判断
- **再検討条件:**
  - INDEX のサマリでは情報不足で詳細議論への遡及頻度が高いと判明
  - `_archive/91_gdr/gdr/` の検索性能が悪く、本文参照に時間がかかる

## 2. 現状

1. **トークン消費が累積する** — ビルドアップ記録・改善提案・Superseded GDR が蓄積するほど、AI セッションの初期読み込みトークンが線形に増える。02 §3.3 で「文書管理の負荷」「トークン消費の増加」と既知化されているが、緩和策は「要約・インデックスを活用」程度の指針止まり
2. **退避という選択肢がない** — 文書ライフサイクルは「能動 → 削除」の二択。古い改善提案ドラフト・対処済みバグレポート・前スプリントのビルドアップ記録などを「能動から外したいが履歴は残したい」場合の置き場がない
3. **Superseded GDR の本文がアクティブ領域に居続ける** — 相互リンクで追跡可能性を確保している一方、本文は `notes/91_gdr/gdr/` に居続けるため、AI が毎セッションで読み込み対象にする
4. **手動運用での命名規約・除外ルールが不在** — 各プロジェクトで「`_old/`」「`archive/`」などの命名が分散し、AI への除外指示も場当たり的

---

## 3. 改善案

`notes/_archive/` 領域を導入し、3 つの GDR で「**退避領域**」「**退避アクション**」「**Superseded GDR の保管方針**」を一体的に定義する。リポジトリにコミットするのは命名規約・キーワード定義・スラッシュコマンド定義のみで、ランタイム依存はない。

1. **`notes/_archive/` の新設と AI デフォルト除外**（GDR-META-016）
2. **`アーカイブ：` キーワードと `/gdr-archive` スラッシュコマンド**（GDR-META-017）
3. **Superseded GDR の二段保管（INDEX 1 行サマリ + 本文 archive）**（GDR-META-018）

## 4. 詳細セクション

### 4.1. `notes/_archive/` ディレクトリ仕様

**配置:**

```
notes/
├── 01_spec/
├── 05_knowledge/
├── 10_things/
├── 20_kaizen/
├── 80_bug_fix_report/
├── 91_gdr/
├── 99_other/
└── _archive/                          ← 新設
    ├── 20_kaizen/
    │   └── 2026-05-01_old_proposal.md
    ├── 80_bug_fix_report/
    │   └── 2026-04-15_fixed_bug.md
    └── 91_gdr/
        └── gdr/
            └── GDR-META-007_old.md
```

**命名規約:**

- `_archive/` は **`_` プレフィックスで標準番号体系（01〜99）の外側を示す**
- 退避ファイルは元のパス構造を保持（`notes/20_kaizen/X.md` → `notes/_archive/20_kaizen/X.md`）
- 復元は `mv notes/_archive/20_kaizen/X.md notes/20_kaizen/` の 1 コマンドで完結

**メリット:**

- 復元時に「どこに戻すか」を考えずに済む
- AI 除外設定が 1 パス（`notes/_archive/`）だけで完結
- ディレクトリ追加・改廃時に archive 側もミラーされる

### 4.2. AI デフォルト除外ポリシー

| ツール | 強制手段 |
|---|---|
| Claude Code | `~/.claude/CLAUDE.md` および プロジェクト `CLAUDE.md` に「`notes/_archive/` は読み込み対象外」を明記。技術的強制が必要な場合は `.claude/settings.json` の `hooks.PreToolUse` で `notes/_archive/` への Read を deny（ユーザー明示指定時のみ allow） |
| Cursor | `.cursor/rules/` に除外ルールを記述 |
| GitHub Copilot | リポジトリ Instructions に明記 |
| 共通 | プロジェクト直下 CLAUDE.md の「ディレクトリ構成」セクションで `_archive/` の役割と除外方針を明示 |

**例外動作:** ユーザーが明示的に `notes/_archive/20_kaizen/2026-05-01_old_proposal.md を読んで` と**個別ファイルのパス指定**をした場合のみ AI が読み込む。「`_archive/` 全体を読んで」のような曖昧指示は拒否し、特定ファイルの指定を求める。

**判定基準:** 個別ファイルの相対パス（`notes/_archive/...` または `_archive/...`）または絶対パスが文中に含まれる場合のみ「明示」と判定する。ディレクトリ指定 / グロブパターン（`_archive/20_kaizen/*.md`）/「archive の X を確認して」のような自然文参照は曖昧扱いとし、AI は「どのファイルを読みますか」と問い返す。

### 4.3. 短縮キーワード「アーカイブ：」と `/gdr-archive`

**短縮キーワード:**

```
アーカイブ：notes/20_kaizen/2026-05-01_old_proposal.md
```

**動作:**

1. 対象ファイルの存在を確認
2. 退避先 `notes/_archive/{元のディレクトリ}/{元のファイル名}` を計算し、必要なディレクトリを作成
3. `git mv` で移動（履歴を保持）
4. 1 コミット（メッセージ例: `docs(archive): move 2026-05-01_old_proposal.md`）

**コンフリクト時:** 退避先に同名既存ファイルが存在する場合は**エラー終了**。ユーザーが既存ファイルを確認・退避先を変更してから再実行する。AI による自動上書き / 自動リネーム（タイムスタンプ付与等）は行わない。

**ディレクトリ指定時:** 引数がディレクトリの場合はディレクトリごと `git mv` で再帰的に退避（サブディレクトリも含む）。ディレクトリ内の各ファイルを個別に動かすのではなく、ディレクトリ単位で 1 コマンド・1 コミットで処理する。

**スラッシュコマンド `~/.claude/commands/gdr-archive.md`:**

```markdown
---
description: 対象ファイルを notes/_archive/ 配下へ退避（元のパス構造保持）
argument-hint: <ファイル or ディレクトリのパス>
---

# /gdr-archive $ARGUMENTS

`$ARGUMENTS` で指定されたファイル/ディレクトリを `notes/_archive/{元のパス}` に退避する。

## 動作
- `git mv` で履歴を保持
- 退避先ディレクトリは自動作成
- 退避後 1 コミット（メッセージ規約あり）
- 物理削除はしない（ユーザーが後で手動 `rm`）

## 例
- `/gdr-archive notes/20_kaizen/2026-05-01_old.md`
  → `notes/_archive/20_kaizen/2026-05-01_old.md`
- `/gdr-archive notes/91_gdr/gdr/GDR-META-007.md`
  → `notes/_archive/91_gdr/gdr/GDR-META-007.md`
```

### 4.4. Superseded GDR の二段保管

**変更前:**

```markdown
# GDR_INDEX

- [GDR-META-007: 旧運用ルール](gdr/GDR-META-007.md) — Superseded by GDR-META-012

# notes/91_gdr/gdr/GDR-META-007.md (本文残存、AI が読み続ける)
**GDR-META-007: 旧運用ルール**
- status: Superseded by GDR-META-012
- 決定: ...
- 理由: ...（長い議論履歴）
```

**変更後:**

```markdown
# GDR_INDEX

- **GDR-META-007**: 旧運用ルール — **Superseded by [GDR-META-012](gdr/GDR-META-012.md)** → archived

# notes/_archive/91_gdr/gdr/GDR-META-007.md (退避済み、AI 除外)
（議論履歴の全文）
```

**ポイント:**

- INDEX 1 行で「過去判断あり / 置換先 / archive 済み」が完結
- AI は INDEX を読むだけで「再検討時にこの GDR を参照すべきか」の判断材料を得られる
- 詳細議論は ROI 視点で「人間が遡る場合のみ」読み込む

### 4.5. 復元手順

```bash
# 単一ファイル（履歴を保持して戻す）
git mv notes/_archive/20_kaizen/2026-05-01_old.md notes/20_kaizen/

# 一括（ディレクトリごと）
git mv notes/_archive/20_kaizen/* notes/20_kaizen/
```

退避時のパス構造をそのまま反転すれば良いため、専用ツールは不要。

**履歴追跡:** 退避経緯は `git log --follow notes/_archive/20_kaizen/X.md` で追跡可能。誤退避は復元 1 コマンドで戻せる。

### 4.6. 退避対象の選定基準

| 対象 | 判断基準 |
|---|---|
| 改善提案・バグレポートの古い版 | 実装完了・対処完了から十分な期間が経過、または後続提案で内容が上書きされた（期間目安はプロジェクトの運用感に応じて決定） |
| Superseded GDR レコード | `status: Superseded` 化後、INDEX に 1 行サマリを記載した時点 |
| ビルドアップ記録の古いセッション | 直近スプリント / マイルストーン以外。引き継ぐべき再検討条件は INDEX に転記 |
| spec 等の旧版 | 新しい仕様書で代替され、現行参照対象でなくなった |
| `_reviewed.md` | **対象外**（`/gdr-apply-review` の標準フローで反映後削除されるため） |

**退避の発火主体:** 初期運用ではユーザー指示時のみ退避する（AI が自律的に「これを退避しましょう」と提案・実行することはしない）。AI 自律退避は半年程度の運用フィードバックを経てから検討する。

## 5. 検討課題

1. **`_archive/INDEX.md` の必要性**
   - 解決策: 当面は不要とし、肥大化（数百ファイル）したタイミングで GDR-META-016 の再検討条件として導入を検討
   - → フェーズ 1 の対象外（YAGNI）

2. **AI ツール側の技術的強制は Claude Code 専用 / Cursor・Copilot で機能しない**
   - 解決策: CLAUDE.md に明記する一次手段で全ツール対応。`.claude/settings.json` の `hooks.PreToolUse` / `permissions.deny` での技術的強制は Claude Code 利用者向けオプションとして 05_CLAUDE_CODE_SETUP に雛形を提示
   - → フェーズ 1 でドキュメント整備、技術的強制の雛形は次回反復で検討（§7.2 参照）

3. **既存プロジェクトへの遡及適用**
   - 解決策: 強制せず、各プロジェクトの運用者判断。GDR-META-016〜018 は「導入時の標準」として T1 / 推奨 CLAUDE.md テンプレに反映
   - → ローカライズ初回プロンプトで雛形を提示

4. **物理削除のタイミング**
   - 解決策: ユーザー手動 `rm`。AI は触らない。タイミング判断は完全にユーザー裁量（年次クリーンアップ / プロジェクト完了時など）
   - → 仕様として明示
