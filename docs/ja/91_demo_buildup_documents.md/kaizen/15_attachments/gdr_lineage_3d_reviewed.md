### A-3. データの埋め込みで、本文の `<!--` と `<script` がページを壊す【そのまま反映可】

**直す先:** [コード] 251 行

`json.dumps(...).replace("</", "<\\/")` は `</script>` だけを防いでいる。HTML の `<script>` 要素の中では、`<!--` の後に `<script` が来ると、最後の `</script>` で要素が閉じなくなる（HTML の構文規則）。

- 確かめたこと: 「決定」の文中に `<!--` と `<script>` の 2 語を（この順で、それぞれバッククォートで囲んで）書いた GDR を 1 件含むディレクトリで生成し、Chrome で開くと、件数の表示もグラフも出ない（スクリプト全体が構文エラーになる）。同じ内容で `<` を `<` に置き換えた版は正常に表示された
- スクリプトの実行には至らない（壊れるだけ）。ただし GDR に HTML コメントや Docsify・サイトの話を書くのは普通にありうる

直し方（1 通り）:

```python
data = json.dumps(datasets, ensure_ascii=False).replace("<", "\\u003c")
```

（`</` の置き換えはこれに含まれる。）

### A-6. 日時の扱い（`uid` の時刻を判定に使っている・読めない日時で誤判定する）【そのまま反映可】

**直す先:** [コード] 154〜165 行（`when`）、528〜534 行（`placeY`）、17 行・263 行（説明）

(1) **`uid` の時刻を日時の順の判定に使っている。** 156 行 `s = r["date"] or r["uidDate"]`。決定は「`uid` の時刻は日時の順の確認に使わない」。確かめたこと: 親が `日時: 2026-12-01`、子が日時なしで `uid`（時刻は 2026-07-01）だけのとき、違反として出る。156 行を `s = r["date"]` にする。縦の位置（529 行）は判定ではないので、そのままでよい。17 行の「『日時』が無い端は uid の時刻で代える」を消し、263 行の「日時が無く uid の時刻で補う GDR（UI-007）」を「縦の位置を uid の時刻で決める」に直す。この修正で、見本とこのリポジトリの違反の件数は変わらない（`uid` があるのは見本の UI-007 だけで、`refines` しか持たない）

(2) **読めない日時を文字列として比べている。** 164〜165 行は、解釈に失敗すると先頭 10 文字を日付として返す。確かめたこと: 親の日時が `未定` や `2026/12/01` だと、子がいつであっても違反になる（文字コードの大小で決まる）。決定は「日時が読めない端では日時を比べない」なので、`None` を返し、読めなかった件数を出す

(3) **結果が Python の版で変わる。** `2026-11-26T12:00:00+0900`（コロンなしのオフセット）は、3.11 以上では解釈でき、3.9 では失敗して日付だけの比較になる。同じ入力で 3.15 は違反 1 件、3.9 は 0 件だった。`fromisoformat` に渡す前に `+0900` を `+09:00` に直す

(4) **読めない日時が 1 つあると、その集合の全 GDR の縦の位置が壊れる。** 529 行の `Date.parse` が `NaN` を返すと、530 行の `v != null` を通り、最小値・最大値が `NaN` になって、全ノードの `fy` が `NaN` になる。確かめたこと: 2 件のうち 1 件の日時を `未定` にすると、2 件とも `fy` と `y` が `NaN` になった（正常な版は ±91）。`NaN` を `null` として扱う

手元の導入先では、日時 163 件のうち 3 件が「オフセット付きの日付時刻」でも「日付のみ」でもない形だった。

### A-7. `uid` の重複の警告が無い。同じ GDR ID が 2 回出ると黙って上書きする【そのまま反映可】

**直す先:** [コード] 92 行、179〜207 行（`check`）、555〜558 行（一覧） [提案 15 §4.9]

- 決定: 「異なる GDR ID に同じ `uid` が付いているもの（警告）を出す」。コードは `uid` を読んで時刻を取り出すだけで、重複を調べていない。確かめたこと: 2 件に同じ `uid` を付けても、形式を満たさない `uid`（大文字・version 4）を付けても、何も出ない
- 92 行 `records[cur["id"]] = cur` は、同じ ID が 2 つの文書にあると後の方で上書きする（リンクは両方から残る）。確かめたこと: 同じ ID で `uid` も status も違う 2 件を読ませると、1 件として表示され、何も出ない。決定は「同じ GDR の写しは同じ `uid` を持つ」としているので、ID が同じで `uid` が違うものは採番の衝突の疑いとして出せる
- **§4.9 の「この決定に合わせて直す点」には 2 点（前提の範囲・`uid` の時刻）しか書かれておらず、`uid` の重複は入っていない。** 足す

直し方: 「不変条件の違反」の一覧に警告として 3 種を足す — 異なる ID に同じ `uid` / 形式を満たさない `uid` / 同じ ID が複数の文書にあって `uid` が違う（`uid` が同じか両方に無ければ写しとして 1 件にまとめ、まとめたことを件数で示す）。
