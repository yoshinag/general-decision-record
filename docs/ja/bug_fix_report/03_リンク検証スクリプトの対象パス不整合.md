# バグレポート: リンク検証スクリプト `scripts/check-links.sh` が存在しないディレクトリを参照して停止する

## 概要

markdown のローカルリンクを検証する `scripts/check-links.sh` が、存在しない `documents/` ディレクトリを走査対象にしており、実行すると `find` のエラーで停止してリンクを 1 件も検証しなかった。kaizen 009 の起票時にリンク検証として実行して発覚し、009 / 010 の実装フェーズではリンク検証を目視と grep で代替していた。

## 発生状況

- **発生時期:** 2026-04-16（`documents/` → `docs/` 移動）以降、潜在的に継続
- **検出:** 2026-09-28、kaizen 009 の起票後にリンク検証として実行
- **症状:**

```
$ bash scripts/check-links.sh
find: documents: No such file or directory
```

`set -euo pipefail` とパイプの組み合わせにより、エラー終了してもリンク検証の結果が何も出ないため、**「壊れたリンクがない」のか「検証していない」のかが出力から区別できない**状態だった。

## 原因

### 原因 1: ディレクトリ移動に追随していない（主因）

スクリプトは 2026-04-13（`1f42835`）に `documents/` 配下を走査する前提で作られた。2026-04-16 の GitHub Pages 対応（[バグレポート 01](/bug_fix_report/01_github_pages_404.md)、`dae74df`）で文書が `docs/` へ移動したが、スクリプトは更新されなかった。

### 原因 2: 絶対パスのリンクを解決できない

同じく バグレポート 01 の対応（`9f4441d`）で、文書間リンクは Docsify のルート（`docs/ja/`）からの絶対パス（`/01_GDR/...`）に統一された。スクリプトはリンクをリンク元ファイルからの相対パスとしてしか解決しないため、仮に走査対象を直しても、**ほぼすべての文書間リンクを「壊れている」と誤検出**する状態だった。

### 原因 3: 1 行に複数のリンクがあると最後の 1 件しか抽出しない

リンク抽出の `sed -n 's/.*\[.*\](\([^)#]*\)).*/\1/p'` は貪欲マッチのため、1 行の最後のリンクしか取り出せない。表の行など、1 行に複数のリンクを持つ箇所で検証漏れが生じていた。

### 原因 4: 失敗が終了コードに反映されない

壊れたリンクを見つけても `BROKEN:` を出力するだけで、終了コードは 0 のままだった（パイプ内の `while` で検出しているため、外側に状態を伝えられない）。CI 等で機械的に判定できなかった。

## 対応

| # | 対応内容 | コミット |
|---|---|---|
| 1 | 走査対象を `docs/` 配下の全 markdown + リポジトリ直下の `README.md` / `CLAUDE.md` / `CHANGELOG.md` に変更 | 本レポートと同じコミット |
| 2 | `/` で始まるリンクを `docs/ja/`（Docsify ルート）からの絶対パスとして解決。アンカー（`#` 以降）は除去、`mailto:` も対象外に追加 | 同上 |
| 3 | `grep -oE '\]\([^)]+\)'` で 1 行内のすべてのリンクを抽出 | 同上 |
| 4 | プロセス置換（`< <(...)`）でループを親シェルに置き、壊れたリンクがあれば終了コード 1 を返す | 同上 |

**検証:**

- 修正後の実行で、`docs/` 配下の http(s) 以外のリンク 138 件がすべて解決し、終了コード 0
- 意図的に壊れたリンクを含む一時ファイルで、絶対パス（`/01_GDR/nope.md`）・相対パス（`missing.md`）の両方を `BROKEN:` として検出し終了コード 1。アンカー付きリンク・`../` を含む相対リンクは正常と判定、インラインコードとコードブロック内のリンクは対象外として無視されることを確認

## 再発防止

- **ディレクトリ構成・リンク記法を変えるときは、それを前提にしたツール（`scripts/` 配下）も連動更新の対象に含める。** CLAUDE.md の「リネーム時の連動更新」の対象は文書（見出し番号・相互リンク・README・サイドバー）に限られており、スクリプトが漏れていた
- **検証ツールは「検証していない」ことを成功と区別できるようにする。** 対象ファイルの走査に失敗したら非ゼロで終了し、壊れたリンクの検出も終了コードに反映する（今回の修正で対応）
- 仕様変更を含む kaizen の実装フェーズの最後に `bash scripts/check-links.sh` を実行する
